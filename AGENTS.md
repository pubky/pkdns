# First Principles

Before planning, implementing, or reviewing any change, read
[our first principles](research/first-principles.md) and check the proposed
approach against them.

Then read [our design principles](research/design-principles.md). Apply them
within the limits set by the first principles. If they conflict, the first
principles take precedence, including over web compatibility goals.

Evaluate whether the change preserves:

- User-controlled identity rooted in public keys and verified signatures.
- Independence from domain registrars and centralized discovery authorities.
- Censorship resistance through DHT discovery and flexible hosting.
- Practical, affordable exit while retaining identity, content, and connections.
- User ownership of content and portability between compatible apps and hosts.

Before completing a task, check the final result against these principles.
If a conflict arises, explain it and propose an approach that preserves them.
Ask for clarification only when the choice materially affects the result.
